# Web UI

## Web UI

Minimalist vanilla-JS UI under `web/` served by nginx on `:8080`, talking to the API via `/api/` reverse-proxy. The tabs — `Cards` (search), `Combos`, `Compare`, `Inventory`, `Wishlist`, `Decks` (saved-deck library), `Deck Building` (the guided deck builder) and `Settings` (collection imports, card-data refresh, import history) — live under a shared header that also parks the light/dark toggle (◐). (The former standalone paste→analyze "Decklist" tab was removed once the Deck Building tab and the Decks-tab evaluation subsumed it; its endpoints — `/decks/analyze`, `/suggest`, `/legality`, `/mulligan`, `/near-combos` — remain shipped and MCP-exposed.) Cards and Combos share the same three-band layout: filter form on top, split results/detail below, footer pager under. Search box accepts the full DSL; result rows show mana cost pips, P/T (when present), and the active sort field (edhrec rank, USD price, release date, colors) with an arrow matching the resolved direction. The order dropdown leads with `best match` (`order=relevance`), which ranks results by trigram word-similarity to the query's bare-word terms — pair with a typo like `invason` to surface Invasion-named cards top of the list. Detail pane exposes keyword and tag chips (type-line tokens, rarity, color combo, format legality) — each chip click appends a single DSL predicate to the search query and reruns, dedup-aware via the `appendPredicate` helper. Detail header carries a `copy id` button (clipboard) and a `Scryfall ↗` link (`card.scryfall_uri`) for round-tripping to the source.

Search box has debounced autocomplete against `/cards/autocomplete` — arrow keys / Enter to pick, Esc to close. Auto-suppressed the moment the query contains DSL operator chars (`: < > = ( ) "`) so name lookups don't fight the DSL. Focusing the empty search box surfaces a "recent" history dropdown; arrow keys navigate, Enter reruns, Backspace on the highlighted entry deletes it. Keyboard shortcuts: `/` focuses the search box from anywhere; `Esc` clears it (or closes the autocomplete/history panel first); `j` / `k` step through result rows and load the highlighted card into the detail pane.

The URL bar mirrors the current query, sort, page, and selected card via `?q=&order=&dir=&page=&id=` — copy the URL to share a result list or a deep-linked card. Defaults are omitted from the URL, so a clean boot is a bare path. Back/forward navigation re-renders against the URL state. A fixed footer pager sits below the results/detail split when the response is multi-page (Scryfall convention: 175 results per page), showing `startIdx-endIdx of total · page N / M` alongside prev/next — same shape as the Combos tab pager so the two surfaces read alike.

Drag the splitter between the result list and the detail pane to resize; the split persists to `localStorage` so it survives reloads. Clamped to a legible range (15–85%) so neither pane fully collapses. Disabled in the mobile vertical stack layout.

Hover any result row, suggest-fill row, or related-card chip for >200ms → floating card image lazy-fetched via `/cards/:id?projection=image_uris,card_faces`. MDFC / transform show the front face only. Debounced (fast mouse-cross doesn't spam requests) and cached per session. `Esc` or `mouseleave` dismisses. Rows that already carry a `data-preview` URL (search results) skip the fetch.

Multi-face cards (transform, MDFC, meld) render every distinct face image stacked with the face name beneath. Click a face to swap the detail body (mana cost, oracle text, P/T, type-line) to that face's data — the active face is outlined in the accent color. The detail pane also surfaces a "Related" chip strip when the card's `all_parts` references other cards (tokens it makes, meld pieces, combo partners) — clicking a related chip navigates to that card so you can walk the graph without re-searching.

A "Combos" section on the detail pane lists every Commander Spellbook combo containing the card (via `GET /cards/:id/combos`). Each combo renders as a collapsed `<details>` — summary is `Card A + Card B → Infinite mana`, expanded body shows clickable card chips (route into `selectCard()` via `card_ids`), plus `Prereqs` / `Steps` / `Produces` prose and two links: `Combo details ↗` (opens the Combos tab pre-selected to that combo via `?tab=combos&combo=<id>`; if the combo isn't on the first page of the default list the tab still renders the full detail by calling `GET /combos/:id` directly) and `Spellbook ↗` (external, `commanderspellbook.com/combo/<id>/`). First 25 entries render inline; overflow surfaces a "Show N more combos" button (some commanders sit in 100+ combos — kept lazy so the initial paint stays cheap). Empty state ("No combos.") when the card exists but has no matches, or when `COMBOS_SOURCE_URL` is set empty.

Predicted role labels surface in two places: a "Predicted labels" chip strip on the detail pane (one chip per label the card scored ≥ 0.5 in `classify_by_rules`, score in the tooltip, click appends `pred:<label>` to the query) and a slot-counts bar above the result list (count of cards on the current page that hit each of `ramp / card advantage / targeted disrupt / mass disrupt / plan`, with the same label-tinted palette as the chips, click drills the search). A card can hit multiple labels (multilabel classifier), so the slot-counts row sum can exceed the page size — that's the slot-count semantic, not a bug.

A "Compare" tab (URL: `?tab=compare`) posts two decklists to `/decks/compare` and renders the diff: `Added` / `Removed` / `Qty changed` card lists plus signed `Slot counts delta`, `Curve delta`, and `Pip delta` chip rows (B − A). Same 64000-char cap per side as `/decks/analyze`. Deep-linkable via `?tab=compare` — analysis state isn't round-tripped (too large; retype or paste).

A "Combos" tab (URL: `?tab=combos`) is a Spellbook-style browser over `GET /combos/search`. Filter inputs sit in a single horizontal strip above the results (same visual pattern as the Cards search bar): comma-separated card names, color-identity string (`WUBRG`; subset match), produced-result substring, and free-text prereqs/steps. Same dual-pane layout as the Cards tab — combo list on the left, full combo detail on the right, drag-splitter between (persisted to `localStorage` under a separate key). List rows show `Card A + Card B` plus the produced-result line; clicking a row renders the full combo body in the detail pane as a MDFC-style card gallery (each card is a `<button class="combo-card face">` with the Scryfall image and the card name as a caption underneath — same shape as multi-face rendering on card detail; Scryfall `small` URLs fetched lazily via `/cards/:id?projection=image_uris,card_faces`, cached per-id for the session; clicking a card in the gallery hops to the Cards tab, rewrites the query to `!"Card A" or !"Card B" …` so the result list is scoped to just this combo, and opens the clicked card in the detail pane), followed by `Produces` (unordered), `Prereqs` (unordered), and `Steps` (ordered) — each line split on `\n` and rendered with the same `renderSymbols()` helper the search UI uses for `{U}` / `{T}` / `{2/W}` mana glyphs, plus a `Spellbook ↗` link. Paginated 25 per page with a footer pager showing `startIdx-endIdx of total · page N / M`; the full filter state serializes into the URL (`?tab=combos&card=Isochron+Scepter&card=Dramatic+Reversal&ci=U`) so links stay shareable. Mobile stacks the split vertically.

### Deck Building (`?tab=build`)

A guided, human-driven deck-builder that walks the 7-step framework in [`docs/edh-guide.md`](edh-guide.md) over a mutable decklist held in `localStorage`. Layout is a left **step menu** (click to jump to any step), a center working area, and a right **decklist sidebar**. Every step drives existing endpoints — no bespoke server surface — so the builder is a composition layer over the API.

- **Sticky scoreboard** (all steps): slot counts vs the `{12 ramp, 12 CA, 12 targeted, 6 mass, 30 plan, 38 land}` template with signed deltas (hover a chip for the class definition), a mana-curve chart with a **dashed guide-target line per mana value**, and the estimated **1–5 power bracket** (`/decks/bracket`).
- **Step 1 — Commander / deck focus.** Set a commander (name box with a commander-only `<datalist>` autocomplete, or `/commanders/suggest` by colors), **load a saved deck** from the library (`GET /decks/:id/cards`), or paste a list. Once set, a **deck-focus** chip strip lets you prioritise the commander's themes; adding a card here pulls its own tags into the pool as suggestions (dashed "new" chips).
- **Steps 3–5 (card advantage / ramp / interaction)** show recommendations as a slot-filtered `/cards/search` (the effective filter is echoed) — reusable `+add` rows with mana-cost glyphs, price and predicted labels. Ramp drops plain fixing/utility lands (keeps lands that make extra mana or fetch lands). Every step carries the commander **theme chips** (each badged with how many deck cards already serve it, via `POST /cards/tag-counts`) so a search can be biased toward the commander; the selection persists across steps.
- **Step 6 — lands & cutting.** Pip-weighted basic fill, per-basic −1, "swap in" a `/decks/manabase` nonbasic that pulls the most-over-pip basic (respecting the land's produced colours), and a **need-vs-sources radar** (colored pips vs mana sources by colour, % share with counts on hover).
- **Step 7 — turn-7 test.** `/decks/goldfish` + `/decks/mulligan`, a **combos** panel (combos present in the deck and combos it's one card away from, via `/decks/combos` + `/decks/near-combos`), then **Save as deck** (`POST /decks`) or copy the list.
- **Decklist sidebar** (right): the current deck grouped by card type (Commander, Creatures, Planeswalkers, Instants, Sorceries, Artifacts, Enchantments, Battles, Lands), CMC-sorted within each group, each row showing qty · name · mana-cost glyphs, with hover previews.

### Decks tab detail pane

Selecting a saved deck shows, at the top of its detail pane, the same **scoreboard** as Deck Building — slot counts vs the template with signed deltas (hover a chip for the class definition), the mana curve with the dashed guide-target line, the estimated **power bracket**, and the **combos present** in the deck — rendered from the deck's HEAD decklist.

Below it, **"Evaluate against the EDH template"** calls [`GET /decks/:id/evaluate`](api.md#get-decksidevaluate) and renders the summary (cards / lands / curve peak / ownership / overlap), a slot table (have / target / Δ), and the improvement tips — `warn` tips (lands, functional slots) and `info` tips (curve shaping, plan headroom, overlap, ownership) distinguished by a coloured left-bar and text weight.

**"Edit in Deck Building"** (in the deck header, beside Fork / Delete) seeds the builder from this deck (`GET /decks/:id/cards`) and switches to it — the round-trip partner of the builder's step-1 "Load a saved deck" picker and step-7 "Save as deck".
